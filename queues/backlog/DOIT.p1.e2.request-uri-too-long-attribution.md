# DOIT.p1.e2.request-uri-too-long-attribution.md - Attribute JSON-Fragment 414 Requests

## Goal

Identify the client, method, framing, and bounded request-line evidence responsible for observed `414 Request-URI Too Long` responses whose retained request-line fragments included `":0,"` and `":1,"`.

## Wording Correction 2026-08-18 - No Complete Request Line Is Claimed

The accepted evidence logs `request_line_complete=false`: the captured bytes are truncated at the parse threshold, so a COMPLETE request line was never captured and is not required for closure. What is proven is the FRAMING defect and its producer - a terminal response to a POST with an unread `Content-Length` body does not close, so the leftover body is parsed as the next request line. Any goal or criterion wording demanding a complete request line is superseded by bounded request-line evidence plus the proven framing owner.
